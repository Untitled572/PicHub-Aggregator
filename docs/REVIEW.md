# 项目检查记录

检查日期：2026-10-01。范围为当前工作区源码、Dashboard 构建、Go 测试和本地模拟请求；没有对线上部署或第三方图源做压力测试。

## 本次已修复

- **健康检测与实际取图配置不一致**：检测原先直接请求主 URL，没有使用默认参数、自定义请求头和应用代理。现在复用取图请求头，并检查主地址及去重后的分支，使用配置的代理和超时。
- **检测结果误判**：原先将 HTTP 400–499 也算作可用。现在检查状态码、图片响应、重定向地址或 JSON 图片字段；限制非图片响应读取量。检测通过仅表示接口响应满足取图规则，不保证下游图片可下载。
- **健康检查覆盖状态**：原先先更新失败次数，再用旧 Source 对象覆盖整行，导致失败次数恢复原值，也可能覆盖刚编辑的配置。现在只更新健康字段。
- **状态提示过于绝对**：取消“节点故障”，区分未检测、本次检测失败、暂停分发和已停用。显示检测时间、失败原因及通过的地址数；编辑图源后的旧检测结果不再直接用于图源卡片，同时修正 SQLite 更新时间被解析成零值的问题。
- **重复检测**：同一轮检测供并发请求复用，最多同时检查四个图源；停用图源跳过。
- **配置导出影响鉴权**：原先导出会清空共享设置缓存的管理 Token。已改为复制后脱敏；导入保留本机认证配置，并检查设置保存结果。
- **导入丢失认证头**：修正请求选项覆盖合并请求头的问题；上传 FormData 时交由浏览器设置 multipart boundary。
- **图片保存失败仍报告成功**：目录创建、写入、同步、关闭、重命名或数据库写入失败会返回错误，避免返回不存在的图片地址。
- **构建流程**：前端构建后自动创建并同步 Go 嵌入资源目录；版本读取不再依赖 Unix 重定向语法。
- **文案和文档**：简化界面措辞，移除无依据的性能及可用性承诺，修正构建顺序和配置说明。

## 建议后续处理

以下问题仍在当前源码中，未包含在本次修复范围。

### 1. 公开管理数据与 URL 探测

`backend/main.go` 将图源列表、配置、备份导出及检测接口公开。`handler/source.go` 直接序列化完整图源，包括自定义请求头。本地模拟已验证未认证请求可以读到图源的 Authorization 值。`service/detector.go` 允许检测回环地址并返回 JSON 内容，本地模拟已验证；如果服务暴露到公网，存在服务器端请求伪造风险。

建议将管理读取、导出与检测纳入鉴权；公共分发接口保留公开。探测还需限制目标协议、解析后的 IP、每次重定向以及响应大小。不要只检查 URL 字符串，或仅增加登录界面。

### 2. 预取池容量混用了历史缓存数量

`backend/service/engine.go` 用 `CountSourceCachedFiles` 决定来源是否达到预取上限。该计数包括已分发的缓存图片；历史缓存达到上限后，即使预取池已空，也可能不再补充该来源。

建议分别计算池内待分发数量与磁盘缓存占用，避免两种限制互相干扰。此项为代码路径检查，尚未做独立运行复现。

### 3. 统计批次失败后可能丢失

`backend/store/batch.go` 在数据库事务提交前清空内存批次，部分执行和提交错误未处理。数据库写入失败时，计数和历史记录可能丢失。

建议事务失败后重试或恢复批次，并在关闭数据库前等待最后一批写入完成。此项为代码检查，尚未注入数据库故障复现。

### 4. 限流器仍保存被拒绝请求

`backend/middleware/ratelimit.go` 在判断是否超限前追加时间戳。持续请求会放大每次扫描和内存开销。

建议使用容量受限的时间队列或令牌桶，并为登录和检测接口设置独立限流。还应使清理周期与配置的限流窗口一致。

- **管理接口鉴权**：图源、设置、统计、历史、导出和检测统一接入现有 AdminAuth。登录页改用只返回登录状态的公开接口；标签、检测结果与备份下载补齐 Bearer 令牌。关闭登录且未配置令牌时仍保持开放模式，公网部署应先完成账号配置。
- **URL 探测限制**：仅接受 HTTP/HTTPS 公网地址，检查实际连接的 DNS 解析结果和重定向，拒绝私网、回环及特殊地址和 URL 凭据；整个探测限时 10 秒，非图片响应最多读取 2 MiB，不通过环境代理发送。已配置图源的取图和健康检测不受此入口限制。
- **统计批次写入**：检查事务开启、SQL 执行和提交错误。失败批次重新并入队列，后续重试；关闭时停止后台任务并等待最后一次写入，失败会返回错误。增加正常退出的 HTTP 请求等待流程。队列仍在内存中，强制终止进程或持续磁盘故障后的退出不能保证尚未写入的数据持久化。
- **限流队列**：被拒绝的请求不再追加时间戳；过期记录按配置的时间窗口清理。每个 IP 保存的请求数受限流阈值约束（调低配置后，旧记录会随窗口到期清除）。
